# 黄金历史数据仓库

## 目标

为量化策略实验室、历史复盘和后续大模型分析提供稳定、可增长、可审计的 XAU/USD 历史行情基础。

第一版优先解决三个问题：

1. 不再把所有历史行情塞进单个大 JSON。
2. 每个周期的数据可以按文件持续增长。
3. 每次写入都做标准化、去重、排序和基础质量检查。

`data/` 目录属于本地运行数据，不提交 Git。

## 数据格式

每根 K 线按 JSONL 保存一行：

```json
{
  "symbol": "xauusd",
  "period": "1d",
  "time": 1761868800,
  "open": 4023.12,
  "high": 4050.33,
  "low": 3998.7,
  "close": 4038.21,
  "volume": 0,
  "provider": "Twelve Data",
  "fetchedAt": "2026-06-06T12:00:00.000Z"
}
```

底层统一使用 UTC 秒级时间戳，前端展示时再转北京时间。

## 已完成基础

- 新增 `marketHistoryStore` 文件型历史仓库服务。
- 旧版 `data/gold-history-cache.json` 会自动迁移到新仓库。
- `goldHistoryService.getLongHistory()` 已优先读取新仓库。
- `goldHistoryService.getCacheSummaries()` 已从新仓库生成概况。
- 写入时会做：
  - 标准化 OHLCV。
  - 按 `symbol + period + time` 去重。
  - 时间升序排序。
  - OHLC 合法性校验。
  - 大时间缺口统计。

## GitHub 长样本导入

第一版长样本使用 BaseMax 的公开 CSV：

- 仓库：[BaseMax/XAUUSD-LSTM](https://github.com/BaseMax/XAUUSD-LSTM)
- 文件：`XAU_15m_data.csv`
- 结构：`Date;Open;High;Low;Close;Volume`
- 许可：MIT License

后端已提供两种导入方式。

命令行导入：

```bash
cd goldpilot-backend
npm run history:import-basemax
```

后端接口导入：

```text
POST /api/research/strategy-lab/history/import-basemax-xau15m
```

接口需要登录态或本地测试账号上下文。默认只允许 `https://raw.githubusercontent.com/` 开头的可选 CSV 地址，避免把导入接口变成任意 URL 抓取器。

导入流程会执行：

1. 下载 CSV。
2. 解析 15 分钟 OHLCV。
3. 转换为 UTC 秒级时间戳。
4. 写入 `xauusd/15m/YYYY-MM.jsonl`。
5. 生成 `manifest.json` 汇总和质量报告。

这份数据适合做长周期回测、参数压力测试和样本切分验证；暂时不作为实时报价源，也不直接用于客户展示的实时行情。

## 后续回填顺序

第一阶段先补中低频，控制 API 配额和数据质量：

1. `1d`：扩到 10 年以上。
2. `4h`：先补 3000-5000 根。
3. `1h`：先补 3000-5000 根。

第二阶段再补短周期：

1. `15m`：1-2 年。
2. `5m`：6-12 个月。
3. `1m`：先补 3-6 个月。

分钟级建议优先用 Dukascopy 分批回填，避免 Twelve Data 免费额度不足。

## 回测使用原则

- 回测只使用真实数据或历史仓库缓存，不使用模拟 K 线。
- 每次策略筛选必须记录：
  - 周期。
  - K 线数量。
  - 数据起止时间。
  - 数据源。
  - 质量提示。
- 策略调参要做训练/验证分段，不能只看单次最高收益。
