# AI交易团队与机器人管家规划

> 目标：把 GoldPilot 的第三板块从“单个 AI交易员”升级为“AI交易团队驾驶舱”。系统仍保持三个主板块：AI智能分析、量化策略实验室、AI交易员；其中 AI交易员板块内部承担策略师、交易员、风控员和机器人管家的协同展示与后续实盘执行入口。

---

## 1. 产品定位

GoldPilot 后续面向客户展示时，不应表达成“一个 AI 黑箱直接下单”，而应表达成一个标准交易团队：

1. **AI策略师**：负责读市场、识别环境、提出策略偏好。
2. **AI交易员**：负责资金分配、执行节奏和机器人调度。
3. **AI风控员**：负责一票否决、降风险、暂停交易和异常处理。
4. **机器人管家**：负责看管 40 个策略机器人，执行启动、暂停、降权、升权和复盘记录。

最终客户感知：

```text
不是 AI 在随便交易，
而是一个由策略师、交易员、风控员组成的 AI 黄金交易团队，
在机器人管家的监督下管理 XAUUSD 策略组合。
```

## 2. 三大板块关系

### 2.1 AI智能分析

定位：策略师晨会与市场判断。

输入：
- TradingView 前端实时盘展示。
- 后端分钟级黄金 K 线。
- 重要数据、事件、快讯。
- 已生成的 AI 分析报告。

输出：
- 黄金方向判断：偏多、偏空、震荡、观望。
- 概率判断：上涨概率、下跌概率。
- 风险级别：低、中、高。
- 当前适配策略：趋势、均值回归、突破、事件、防守。
- 当前禁用策略：高风险马丁、激进突破、数据窗口剥头皮等。

### 2.2 量化策略实验室

定位：策略研究部和策略体检表。

输入：
- 40 个黄金策略定义。
- 后端模拟盘运行结果。
- 逐笔模拟交易、权益曲线、每日结算。

输出：
- 策略评分。
- 策略状态建议：运行、观察、暂停。
- 策略资金建议。
- 策略风险标签。
- 给 AI交易员 的候选策略列表。

### 2.3 AI交易员

定位：AI交易团队驾驶舱。

输入：
- AI策略师观点。
- 量化实验室策略评分。
- 账户净值、持仓、回撤、交易频率。
- 风控规则。

输出：
- 启动哪些机器人。
- 暂停哪些机器人。
- 给每个机器人分多少钱。
- 是否允许实盘执行。
- 风控是否通过。
- 交易动作日志。

## 3. AI交易团队角色拆分

### 3.1 AI策略师

职责：
- 判断黄金市场状态。
- 判断当前更适合哪类策略。
- 判断重要数据窗口是否需要降风险。
- 给交易员提供策略偏好，而不是直接下单。

核心输出字段：

| 字段 | 示例 | 说明 |
| --- | --- | --- |
| marketState | 震荡偏多 | 市场结构 |
| directionBias | long / short / neutral | 方向偏好 |
| confidence | 55 | 方向置信差 |
| preferredMethods | 均值回归、低密度网格 | 当前适合策略类型 |
| blockedMethods | 马丁、激进突破 | 当前不适合策略类型 |
| eventRisk | 中等 | 事件风险 |
| note | 美盘数据前降低激进策略 | 策略师说明 |

### 3.2 AI交易员

职责：
- 读取策略师观点。
- 读取策略实验室运行表现。
- 决定策略组合资金权重。
- 决定运行、观察、暂停。
- 只在风控员允许后执行。

核心输出字段：

| 字段 | 示例 | 说明 |
| --- | --- | --- |
| mode | 防守运行 | 今日执行模式 |
| activeRobots | 18 | 启用机器人数量 |
| observeRobots | 13 | 观察机器人数量 |
| pausedRobots | 9 | 暂停机器人数量 |
| capitalInUse | 680000 | 已分配策略资金 |
| cashReserve | 320000 | 现金缓冲 |
| executionNote | 稳健策略优先，激进策略轻仓观察 | 执行说明 |

### 3.3 AI风控员

职责：
- 独立审核交易员动作。
- 拥有一票否决权。
- 管理最大日亏损、最大回撤、单策略亏损、连续亏损和异常连接。

硬风控规则：

| 风控项 | 建议初始值 | 动作 |
| --- | --- | --- |
| 单策略最大资金 | 8% | 超过则拒绝 |
| 激进策略总资金 | 20% | 超过则拒绝 |
| 日亏损警戒线 | -2% | 降仓 |
| 日亏损熔断线 | -4% | 停止开新仓 |
| 总回撤警戒线 | -6% | 降低所有策略权重 |
| 总回撤熔断线 | -10% | 全部暂停 |
| 连续亏损 | 3 笔 | 策略降权 |
| 连续亏损 | 5 笔 | 策略暂停 |
| 行情断流 | 30 秒无更新 | 禁止新开仓 |
| 重大数据窗口 | 前后 10-15 分钟 | 降低激进策略 |

### 3.4 机器人管家

职责：
- 看管每个策略机器人。
- 记录机器人状态变化。
- 维护机器人档案。
- 把策略实验室结果翻译成运行队列。

机器人状态：

| 状态 | 说明 |
| --- | --- |
| 主力运行 | 资金权重正常，允许开仓 |
| 轻仓运行 | 允许开仓但降低仓位 |
| 观察运行 | 只模拟或只记录信号 |
| 暂停开仓 | 不允许新开仓，已有仓位按规则处理 |
| 风控冻结 | 因异常或亏损触发，不可手动绕过 |

## 4. 决策链路

标准链路：

```text
行情/事件/历史K线
  -> AI策略师：输出市场观点
  -> 量化策略实验室：输出策略评分
  -> AI交易员：生成资金分配和机器人运行计划
  -> AI风控员：审核并允许/降级/拒绝
  -> 机器人管家：执行启动、暂停、降权、记录动作
  -> 模拟盘/实盘执行层
  -> 交易流水、权益曲线、每日结算、审计日志
```

任何交易动作必须可追溯：

```text
为什么启动？
依据哪个市场状态？
参考哪个策略评分？
风控是否通过？
分配了多少钱？
如果亏损，谁负责暂停？
```

## 5. 策略评分模型

第一版策略评分可以使用透明加权，不需要复杂机器学习：

```text
策略总分 =
  当前市场适配度 * 25%
+ 近期收益表现 * 20%
+ 胜率稳定性 * 15%
+ 最大回撤控制 * 20%
+ 交易样本数量 * 10%
+ AI方向一致性 * 10%
- 连续亏损惩罚
- 高波动惩罚
- 重大数据惩罚
```

评分档位：

| 分数 | 档位 | 动作 |
| --- | --- | --- |
| 80-100 | A | 主力运行 |
| 65-79 | B | 正常运行 |
| 50-64 | C | 观察运行 |
| 35-49 | D | 暂停开仓 |
| 0-34 | E | 风控冻结 |

第一版前端可用策略标签和风险分模拟展示，后端后续接入真实运行结果后替换。

## 6. 资金分配模型

当前落地模型：40 个策略交易员，每个独立 1,000,000 美元模拟本金，总测试资金 40,000,000 美元。

每个策略交易员独立核算：

| 字段 | 说明 |
| --- | --- |
| 本金 | 固定 1,000,000 美元 |
| 权益 | 本金 + 已实现盈亏 + 浮动盈亏 |
| 盈亏 | 当前模拟运行净盈亏 |
| 收益率 | 盈亏 / 独立本金 |
| 胜率 | 已平仓交易中盈利交易占比 |
| 回撤 | 运行权益曲线最大回撤 |
| 交易笔数 | 已生成并保存的逐笔模拟交易数量 |

AI交易员不是把 4,000 万全部平均启用，而是只从“盈利稳定、回撤低、样本足够”的策略里选主力运行。其他策略进入观察、降权或冻结队列。

AI交易员实际选择时，必须先经过风控员修正：

```text
基础权重 -> 策略评分修正 -> 市场状态修正 -> 风控上限修正 -> 最终权重
```

当前第一版风控动作：

| 条件 | 动作 |
| --- | --- |
| 盈利、交易样本 >= 8、胜率 >= 45%、最大回撤 <= 6%、PF >= 1.05 | AI精选 |
| 当前亏损或连续亏损 >= 3 笔 | 降权 |
| 连续亏损 >= 5 笔或最大回撤 >= 10% | 冻结 |
| 观察策略 | 收集样本，不进入 AI主力池 |

## 7. 页面布局规划

### 7.1 AI交易员首页首屏

首屏必须让客户一眼明白：

```text
这是一个交易团队，不是单个按钮。
机器人有人管，风险有人管，交易有记录。
```

首屏结构：

1. 顶部标题：AI交易员 / AI黄金交易团队。
2. 主视觉：四角色中控台。
3. 右侧资金状态：模拟资金、已分配、现金缓冲、风控状态。
4. 角色卡片：策略师、交易员、风控员、机器人管家。

### 7.2 中部执行区

展示交易员和风控员的协同：

1. 今日执行模式：防守、均衡、进攻、熔断。
2. 当前启用机器人数量。
3. 当前观察机器人数量。
4. 当前暂停机器人数量。
5. 风控审批状态。
6. 管家最近动作。

### 7.3 底部机器人区

保留现有机器人模板和我的机器人，但语义调整：

1. 模板机器人 = 可创建的执行机器人。
2. 我的机器人 = 管家名下的机器人档案。
3. 每个机器人显示：状态、风险、策略、权益、盈亏、操作。

## 8. 实盘对接阶段

实盘对接必须分阶段，不允许直接进入全自动实盘。

### 阶段 1：模拟盘

当前阶段。

目标：
- 策略运行能持续保存。
- 机器人状态能解释。
- 风控规则能展示。
- 客户能看懂交易团队怎么工作。

### 阶段 2：只读实盘

接真实账户，但只读：

- 账户余额。
- 净值。
- 持仓。
- 订单。
- 历史成交。

不允许下单。

### 阶段 3：半自动实盘

AI交易员生成建议，用户确认后下单。

流程：

```text
AI交易员建议 -> 风控员审核 -> 用户确认 -> 执行层下单
```

### 阶段 4：自动实盘

仅在模拟盘和半自动阶段稳定后开启。

必须具备：
- 硬风控熔断。
- 下单审计日志。
- 账户只读监控。
- 断线保护。
- 最大亏损保护。
- 人工一键停止。

## 9. 接入路线建议

### 9.1 OANDA API

适合：
- XAUUSD 流式行情。
- 后端自动化。
- 模拟账户测试。

优势：
- 不需要客户端常开。
- PricingStream 适合后续 10 秒行情聚合。
- 与前端 TradingView 的 OANDA:XAUUSD 展示源一致。

### 9.2 MT5 / MetaAPI

适合：
- 客户已有 MT4/MT5 账户。
- 跟单式展示。
- 实盘账户只读和执行桥接。

注意：
- MT5 登录密码不是 OANDA v20 API Token。
- 直接后端连接 MT5 通常需要客户端或云桥接。

### 9.3 IBKR

暂不作为第一优先级。

原因：
- API 接入复杂。
- 实时行情通常涉及市场数据订阅。
- 黄金现货/差价合约不是当前最短路径。
